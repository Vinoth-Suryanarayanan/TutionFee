# Step 1 — Project setup and configuration

**Goal:** an empty-but-real Python project that installs with one command, reads its settings
from a file instead of hard-coded values, and makes it impossible to accidentally commit real
family data.

**Run it:**

```bash
uv sync                      # create .venv and install dependencies from uv.lock
cp .env.example .env         # your local, private settings
uv run python -c "from tuition.config import get_settings; print(get_settings())"
```

## `pyproject.toml` — the project's identity card

The one file every modern Python tool reads (uv, pip, ruff, pytest).

| Line(s) | What it does | Why |
|---|---|---|
| `[project]` | Starts the standard package metadata table (PEP 621). | Any tool can read the name, version, dependencies. |
| `name = "tuition-fee-agents"` | Distribution name (what you'd `pip install`). | Hyphens are normal for distribution names; the importable package is `tuition`. |
| `version = "0.1.0"` | Semantic version. `0.x` = not stable yet. | Signals honestly that this is early. |
| `description`, `readme`, `license` | Shown on GitHub/PyPI. | Makes the repo self-describing. |
| `requires-python = ">=3.11"` | Refuse to install on older Python. | We use `StrEnum` (added in 3.11). |
| `dependencies = [...]` | Runtime libraries. **Only two for now.** | We add each library in the step that first uses it (`uv add sqlalchemy` in Step 2), so you see why each one exists. |
| `pydantic` | Data validation using type hints. | Turns the text `"5"` from `.env` into the integer `5`, and rejects bad values early. |
| `pydantic-settings` | Pydantic + reading env vars / `.env`. | Gives us typed config in ~15 lines. |
| `[dependency-groups] dev` | Tools only developers need. | `pytest` (tests) and `ruff` (lint + format) aren't installed for end users. |
| `[build-system]` / `hatchling` | How to turn `src/` into an installable package. | Lets `uv sync` install our own code in "editable" mode so `import tuition` works everywhere. |
| `[tool.hatch.build.targets.wheel] packages = ["src/tuition"]` | Tells hatchling where our code lives. | We use the **src layout**: code under `src/` can't be imported by accident from the repo root, so tests always run against the installed package — a common source of "works on my machine" bugs avoided. |
| `[tool.ruff]` `line-length = 100`, `target-version = "py311"` | Formatting width and which Python syntax to assume. | One consistent style; no style debates in reviews. |
| `[tool.ruff.lint] select = [...]` | Which rule families run. `E/F` = errors & pyflakes, `I` = import sorting, `B` = bugbear (likely bugs), `UP` = modern syntax, `SIM` = simplifications, `RUF` = ruff's own. | A sensible, not-too-noisy baseline. |
| `[tool.pytest.ini_options]` | Where tests live, quiet output. | Used from Step 2 on. |

## `uv.lock`

Generated by `uv sync`; never hand-edited. It pins the exact version (and hash) of every
package, including dependencies of dependencies. Anyone cloning the repo gets an identical
environment. **Commit it.**

## `.env.example` vs `.env`

* `.env.example` is committed: it documents every setting with safe example values.
* `.env` is your copy with real values; it is git-ignored.

Each line is `NAME=value`. Pydantic matches names case-insensitively to fields in `config.py`
(`BILLING_DUE_DAY` → `billing_due_day`).

| Setting | Meaning |
|---|---|
| `DATABASE_URL` | Where Postgres is. `postgresql+psycopg://user:password@host:port/dbname`. `+psycopg` names the driver SQLAlchemy will use. Used from Step 2. |
| `SCHOOL_NAME` | Appears in reminders. Lets anyone reuse the project for their own school. |
| `CURRENCY` | ISO code for display. |
| `BILLING_DUE_DAY` | Fees are due on this day of the month. |
| `BILLING_POLICY` | When a month is billable — if the student was enrolled on *any* day of the month, or only if enrolled on the 1st. A real business rule, so it's config, not code. |
| `REMINDER_MIN_BALANCE` | Don't nag a parent over a few cents left by PayPal rounding. |
| `PRIVATE_DATA_DIR` | Where your real statement exports go. |

## `.gitignore` — the privacy guardrail

The first block is the important one:

```gitignore
.env                    # real settings / API keys
data/private/*          # everything in data/private ...
!data/private/README.md # ... except this README (the "!" re-includes it)
*.db
*.sqlite                # any local database file
```

This is a design decision, not housekeeping: the repo is meant to be public, so the *default*
must be that real data can't be committed even by mistake. The remaining lines ignore Python
build/cache output and editor files.

## `src/tuition/config.py` — typed settings

```python
from __future__ import annotations
```
Treats type hints as strings, evaluated lazily. Allows forward references and is standard in modern code.

```python
from decimal import Decimal
from enum import StrEnum
from functools import lru_cache
from pathlib import Path

from pydantic_settings import BaseSettings, SettingsConfigDict
```
Standard-library imports first, third-party second (ruff's `I` rule enforces this order).
* `Decimal` — exact decimal arithmetic. **Money is never a float**: `0.1 + 0.2 == 0.30000000000000004` in float.
* `StrEnum` — an enum whose members are also strings.
* `lru_cache` — caches a function's result.
* `Path` — filesystem paths as objects instead of strings.

```python
class BillingPolicy(StrEnum):
    """When does an enrollment owe a month's fee?"""

    FULL_MONTH_IF_ENROLLED_ANY_DAY = "full_month_if_enrolled_any_day"
    FULL_MONTH_IF_ENROLLED_ON_FIRST = "full_month_if_enrolled_on_first"
```
A closed set of allowed values. If `.env` says `BILLING_POLICY=prorated`, startup fails with a
clear error instead of silently doing something else. Because it's a `StrEnum`, a member compares
equal to its string and serializes cleanly to JSON/DB.

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8", extra="ignore")
```
* Subclassing `BaseSettings` means: "fill each field from environment variables, then `.env`, then the default."
* `env_file=".env"` — read the file in the current directory, if present.
* `extra="ignore"` — unknown keys in `.env` don't crash startup (useful as the file grows).

```python
    database_url: str = "postgresql+psycopg://tuition:tuition@localhost:5432/tuition"
```
Each line is `name: type = default`. The type drives validation and conversion.

```python
    school_name: str = "Example Learning Center"
    currency: str = "USD"
    billing_due_day: int = 5
```
`.env` values are always text; pydantic converts `"5"` → `5` and rejects `"five"`.

```python
    billing_policy: BillingPolicy = BillingPolicy.FULL_MONTH_IF_ENROLLED_ANY_DAY
    reminder_min_balance: Decimal = Decimal("1.00")
```
Note `Decimal("1.00")` built from a **string** — `Decimal(1.00)` from a float would carry the float's imprecision.

```python
    private_data_dir: Path = Path("data/private")
```
Converted to a `Path` so later code can do `settings.private_data_dir / "paypal.csv"`.

```python
@lru_cache
def get_settings() -> Settings:
    return Settings()
```
Settings are read once and the same object is returned on every call. Everywhere else in the code
calls `get_settings()` rather than reading env vars directly — one place to look, and tests can
override it.

## Design decisions made in this step

1. **Config over code** — anything school-specific is a setting, so others can reuse the project.
2. **Private by default** — `.gitignore` is written before any data exists.
3. **Add dependencies when they're needed** — keeps every line in `pyproject.toml` explainable.
4. **`Decimal` for money from day one.**
